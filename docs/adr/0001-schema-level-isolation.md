# ADR-0001: DB分離はスキーマ + ロール権限で実現する

- ステータス: 採用
- 日付: 2026-08-19

## 背景

Database per Service が MES ドメインで成立するかを検証したい。
教科書的な実装はサービスごとに別DBインスタンスを立てることだが、
検証の主眼は「論理的な境界が守れるか」であり、インフラの物理分離ではない。

また、利用可能な環境として既に稼働中の Postgres が1台ある。

## 決定

単一 Postgres インスタンス上に、サービスごとの **スキーマ + 専用ログインロール** を作り、
ロールに自スキーマ以外の `USAGE` 権限を与えないことで分離を強制する。

- 各サービスは自分のロールでのみ接続する
- `search_path` はロール単位で自スキーマに固定する
- DDL は別の管理ロールで実行し、サービスロールには与えない
- スキーマ跨ぎの外部キーは（権限がないため）作れない

## 理由

- 「規約で気をつける」ではなく **DBが越境を実行時に拒否する**ため、分割の成立が自動判定できる
- E2E テストが通ること自体が、越境していないことの証明になる
- 物理分離へ移行する場合、アプリ側は接続文字列の差し替えのみで済む

## 結果

**得られるもの**
- 論理的な分割可能性の検証
- 越境の自動検出

**得られないもの（検証範囲外として明記する）**
- 障害の独立性（インスタンス障害は全サービスに波及する）
- 個別のスケーリング・チューニング
- DBエンジンの個別選択
- バックアップ/リストアの完全な独立

これらは検証レポートで「スキーマ分離で検証できた範囲」と「できていない範囲」として区別して記載する。
