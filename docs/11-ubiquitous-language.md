# 11. ユビキタス言語（Phase B-3）

## 原理

**同じ言葉が文脈によって違う意味を持つなら、そこに境界がある。**

逆に、無理に1つの意味へ統一しようとすると、どこかで嘘をつくことになる。
意味がズレる場所は、境界の強い証拠として扱う。

## 文脈によって意味が変わる概念

### ロット

| 文脈 | 意味 |
| --- | --- |
| 在庫 | 同一条件で入荷/製造された**数量のまとまり**。在庫の単位 |
| 製造実行 | 1回の作業で流す**製造単位**（製造ロット）。在庫のロットとは粒度が違う |
| 品質 | **検査の単位**。製造ロットを分割/統合して検査することがある |

> 本プロジェクトのスコープには品質検査を含まないため、
> 当面は「在庫のロット」と「製造ロット」の2つを扱う。

### 品目

| 文脈 | 意味 |
| --- | --- |
| マスタ | 品目の**仕様**。名称・単位・BOM・工程を持つ、太った概念 |
| 在庫 | **在庫を数える単位**。必要なのはコードと単位だけ |
| 生産指示 | **製造対象**。コードと、発行時点の名称・単位のスナップショットだけ |

### オーダー

| 文脈 | 意味 |
| --- | --- |
| 生産指示 | **何をいくつ作るかの計画**。工程と所要材料を持つ、中身の詰まった集約 |
| 製造実行 | 実績を紐づける**参照キー**。中身にはほぼ関心がない |
| 在庫 | 引当と系譜の**参照キー**。同じく中身に関心がない |

> **「オーダー」は文脈によって太さが全く違う。**
> 生産指示にとっては集約だが、実行と在庫にとってはただの文字列キーである。
> この非対称性が、境界を引く強い根拠になる。

### 数量

MES で「数量」と一言で言うと必ず事故る。語彙を分けて固定する。

| 用語 | 識別子 | 意味 | 主な文脈 |
| --- | --- | --- | --- |
| 計画数 | `planned_qty` | オーダーで作ると決めた数 | 生産指示 |
| 所要数 | `required_qty` | 計画数を作るのに必要な材料の数 | 生産指示 |
| 引当数 | `allocated_qty` | オーダー向けに確保された在庫数 | 在庫 |
| 払出数 | `issued_qty` | 在庫から実際に出した数 | 在庫 |
| 投入数 | `consumed_qty` | 作業で実際に使った数 | 製造実行 |
| 良品数 | `good_qty` | 作業で得られた良品の数 | 製造実行 |
| 不良数 | `scrap_qty` | 作業で発生した不良の数 | 製造実行 |
| 完成数 | `completed_qty` | オーダーとして完成した数 | 生産指示 |
| 在庫数 | `on_hand_qty` | 現時点の手持ち在庫数 | 在庫 |

**保留**：「払出数」と「投入数」を区別するかは業務判断である。
払い出したが使わず残る場合に差が出る。当面は同一視して進め、
必要になった時点で分ける（Phase C-4 で再検討）。

## 方針（ADR-0009）

**コンテキストごとに別モデルを持つ。**
同じ「品目」でも、文脈ごとに必要な属性だけを持つ別の型として定義する。

### 命名の目安

| コンテキスト | 品目を表す型 | 持つ属性 |
| --- | --- | --- |
| マスタ | `Item` | コード、名称、単位、区分、ロット管理要否、有効フラグ |
| 生産指示 | `OrderItem` | コード、発行時点の名称・単位のスナップショット |
| 在庫 | `StockItem` | コード、単位、ロット管理要否 |

**同じ名前の型を、複数のコンテキストで共有しない。**
共有した時点で、変更の波及が止まらなくなる。

### 引き受けるコスト

案1 を選んだ以上、以下は設計上のコストとして引き受ける。

- 同じ情報が複数箇所に存在する
- 変換（マッピング）コードが必要になる
- 「品目名を直したのに在庫画面に反映されない」といった**一貫性の問題が業務として発生する**

3つ目は隠さず、業務ルールとして扱う（いつ・どう同期するかは Phase D-2 で決める）。

### 陥ってはいけない状態

- 変換層を作らず DTO をそのまま引き回し、結局全コンテキストが同じ形に依存する
- 「別モデルにする」と言いながら属性を全部コピーし、同じ太さのモデルが4つできる
  → **マッピングコストだけ払って分離の利益がない、最悪のパターン**

**判定基準**：各コンテキストのモデルが、マスタのモデルより**明確に痩せている**こと。
痩せていなければ、そのコンテキストは本当にその属性を必要としているか問い直す。
